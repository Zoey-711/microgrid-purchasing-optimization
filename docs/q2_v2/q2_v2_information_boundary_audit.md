# 问题2新版：信息边界与因果审计设计

## 1. 每日信息集

设决策日为 \(d\)。所有日期比较均使用完整日期而非文件行号猜测。

| 时点 | 允许读取 | 禁止读取 | 可作决策 |
|---|---|---|---|
| 日期 \(d\) 的0:00 | 日期严格早于 \(d\) 的实际负载、实际光伏及其因果历史预测残差；附件1固定电价；本策略由上一日实际执行得到的当前SOC | 日期 \(d\) 及之后的实际负载、实际光伏；附件1负载/光伏预测；附件3、附件4；问题3预报与参数 | 一次性锁定当天144槽 \(p_{d,t}\)，构造当天历史联合情景与DP未来价值 |
| 实际槽 \(t\) 到达时 | 当前槽实际负载、当前槽实际光伏、当前SOC、0:00已锁定计划、0:00已冻结的情景和价值函数 | 槽 \(t+1\) 及之后的当日实际数据、未来紧急购电和未来SOC | 选择当前槽充电或放电动作，计算当前紧急购电与弃电 |
| 日期 \(d\) 执行结束后 | 当天全部实际数据、当天0:00预测、执行结果 | 不得回写或改变当天已锁定计划 | 生成当天预测残差，加入后续日期历史缓冲区；实际末SOC传给下一日 |

计划一经0:00确定即不可修改。实时执行器可以使用历史场景产生的未来价值，但不能重新读取同日未来真实数据。

## 2. 因果预测回放

### 2.1 负载

对槽 \(t\)，令

\[
\mathcal W_d=\{i<d:\operatorname{weekday}(i)=\operatorname{weekday}(d),\ d-i\le35\text{天}\}.
\]

若 \(\mathcal W_d\neq\varnothing\)，使用其中全部可用日的同槽均值；否则使用日期 \(d\) 之前最近至多7个完整日的同槽均值。2025-01-01没有任何历史，预测固定为0。

### 2.2 光伏

使用此前 \(m_d=\min(7,d-1\text{的可用完整日数})\) 个已完成日同槽均值。2025-01-01预测固定为0。

每个历史日必须保存其当天0:00真正可得的预测版本。残差

\[
\varepsilon^L_{i,t}=L^{\mathrm{actual}}_{i,t}-\widehat L_{i,t},\qquad
\varepsilon^{PV}_{i,t}=PV^{\mathrm{actual}}_{i,t}-\widehat{PV}_{i,t}
\]

只能在日期 \(i\) 完整结束后进入历史残差池。禁止在年底用全量数据重新生成1月历史预测残差。

## 3. 联合残差情景信息边界

日期 \(d\) 的候选情景日集合只取最近 \(M\) 个满足以下条件的日期 \(i\)：

1. \(i<d\)；
2. 日期 \(i\) 已完整结束；
3. \(i\) 日的负载与光伏预测均是当时因果生成；
4. 负载、光伏残差来自同一个历史日，144槽整条轨迹共同保留。

不得分别抽样负载残差和光伏残差，不得打乱槽序，不得用日期 \(d\) 的任何实际量修正当天场景。历史不足时使用 \(M_{\mathrm{eff}}\)，并把实际使用日期逐日输出。

## 4. 冷启动、开发期和评价期

- 所有策略独立从2025-01-01 0:00的6000 kWh开始；
- 1月1日无历史，点预测和计划购电量取0；实时仅按当前实际供需、储能和紧急购电规则执行；
- 1月初用于积累预测与残差；拟采用1月22—31日作为共同开发评价窗口；
- 参数候选在该窗口内逐日因果回放，不能共享不同策略的SOC；
- 2月1日至12月31日为334天正式评价期，阶段3选定参数后必须锁定；
- 正式期不得调参。若正式结果已被查看后再提出新候选，其比较必须标记为事后改进，不得称为未触碰测试。

对于 \(M=30\)，1月22日前可用残差不足30天。阶段3须把 \(M\) 定义为“最大回看天数”，使用 \(M_{\mathrm{eff}}\) 并报告每日有效情景数；若要求所有候选都达到完整 \(M\)，共同开发期将缩短到1月31日，统计支撑较弱。两种口径不能混用。

## 5. 后续必须输出的逐日审计字段

| 字段 | 含义 |
|---|---|
| `decision_date` | 当前0:00决策日 |
| `load_history_dates` | 负载点预测使用的完整历史日期 |
| `pv_history_dates` | 光伏点预测使用的完整历史日期 |
| `residual_scenario_dates` | 联合残差情景日期，负载与光伏共用 |
| `max_load_source_date`、`max_pv_source_date`、`max_scenario_date` | 各数据源的最晚日期 |
| `all_source_dates_strictly_before_decision` | 三类日期是否均严格早于决策日 |
| `scenario_count_requested`、`scenario_count_effective` | 请求与实际情景数 |
| `soc_start_kwh`、`soc_end_kwh` | 实际跨日SOC |
| `plan_locked_at_00` | 计划是否在0:00后保持不变 |
| `future_actual_access_count` | 当日未来实际值访问次数，必须为0 |
| `attachment3_access_count`、`attachment4_access_count` | 禁用附件访问次数，必须为0 |

同时保存每条历史预测的 `forecast_created_at`、`target_date`、`target_slot`、数据截止日和预测值，使任一残差都可追溯到当时信息集。

## 7. 阶段 2 补充审计规则

- 连续 3 天机制测试的 6000 kWh 初值仅是独立测试初值，不代表全年连续运行到该日期时应有的真实 SOC；测试内部仍逐日跨日传递。
- 每个决策日使用的负载预测历史日、光伏预测历史日和联合残差情景日必须严格早于决策日；历史不足时只缩小有效样本数，不补造、不重复。
- 日前计划一经生成即锁定。实时执行只接收当前槽真实负载、当前槽真实光伏、当前 SOC、锁定计划以及 0:00 已形成的平均路径价值。
- 修改尚未到达的未来实际负载或光伏后，修改时点以前已经生成的预测和动作必须保持不变；该扰动测试作为阶段 2 的因果性单元测试。
- 2—12 月正式评价前，必须先在 1 月开发期冻结模型结构和参数；正式期不得承担二次选择功能。

## 8. 阶段3实测结论

- 共同开发评价期固定为2025-01-22至31日，未依据紧急购电量挑选日期；1月1日至21日为连续预热。
- 每个候选从相同的2025-01-01 0:00、6000 kWh出发，按各自实际动作连续传递SOC；评价期开始时没有重置。
- 所有点预测历史日期及联合残差情景日期均严格早于决策日，信息日期违规数为0。
- M14在评价期每天实际使用14条历史情景；M21每天使用21条；M30从21条逐日增至30条。
- 正式评价参数已依据1月开发期冻结；尚未读取或运行2—12月正式评价结果。
- 选定策略逐槽计划锁定误差、跨日SOC衔接误差均为0；没有访问附件3、附件4或问题3数据。
