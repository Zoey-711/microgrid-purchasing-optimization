# 问题三 V2：调整结算主假设与人工核验

## 1. 主假设

令 \(p_{d,t}\) 为当天 0:00 原计划购电量，\(z_{d,t}\) 为槽位执行前最后一个已发布且有效的购电版本。定义

\[
\delta^+_{d,t}=(z_{d,t}-p_{d,t})^+,
\qquad
\delta^-_{d,t}=(p_{d,t}-z_{d,t})^+.
\]

合同费用采用

\[
C^{\mathrm{contract}}_{d,t}
=\pi_t p_{d,t}+1.5\pi_t\delta^+_{d,t}-0.5\pi_t\delta^-_{d,t}.
\]

其含义是：保留的原计划电量按正常价格结算；超过原计划部分按 1.5 倍价格结算；取消部分退还原价的 50%，剩余 50%构成取消成本。每槽只用执行前最终生效量相对 0:00 原计划结算一次，不累计中间计划版本的费用。该式已经作为问题三 V2 的工程主解释，但**属于建模假设，并非题面已作唯一确认的会计规则**。

紧急购电独立按 \(5\pi_t e_{d,t}\) 结算，因此

\[
C^{\mathrm{actual}}_{d,t}=C^{\mathrm{contract}}_{d,t}+5\pi_te_{d,t}.
\]

不得再额外叠加 \(\pi_tz_{d,t}\) 或另一遍原计划费；终端库存价值也不得从实际账单中扣除。

## 3. 滚动优化与实际账单的区别

6:00、12:00、18:00 的滚动 MILP 都对尚未执行后缀使用同一个 \(C^{\mathrm{contract}}(p,z)\) 函数；此前已执行费用只作为历史常数，不参与新后缀决策。优化器各版本的目标值只用于选择该版本方案，不能跨版本累加，也不能替代最终逐槽实际账单。
