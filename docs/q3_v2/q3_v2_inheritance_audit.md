# 问题三 V2：与问题二 V2 的继承一致性审计

## 1. 审计边界与结论

本审计仅读取旧问题三的设计、代码、核验记录，以及已冻结问题二 V2 的设计和实现记录；未运行任何优化，未创建或修改 `result3.xlsx`，也未改动问题一、问题二 V2 或旧问题三文件。

结论是：**储能物理口径、官方槽位映射、因果审计框架、附件 3 的发布时间—目标时刻解析，以及“最终生效量相对 0:00 原计划逐槽结算一次”的主解释可以继承；旧问题三的点预测日前 LP、6000 kWh 软保留、参考 SOC 阈值贪心执行器和旧全年数值不能直接作为问题三 V2 的正式结果。**

问题三 V2 应采用“多版本预测—滚动共同计划调整—动态价值实时执行”的结构。其中，问题二 V2 的动态价值执行器需按每次购电版本的尚未执行后缀重新构造价值函数；不能将以原计划形成的价值函数在购电调整后继续使用。

## 3. 逐模块继承判断

完整逐项矩阵见 `outputs/q3_v2/audit/q3_v2_inheritance_matrix.csv`。关键判断如下。

### 3.1 可以直接继承的模块

1. **统一物理口径。** 保持 144 个连续 10 分钟槽位，代码索引 `t=0,...,143`，SOC 状态为 145 个；所有调度变量为 kWh，功率数据先乘 \(\Delta t=1/6\) h。SOC 转移保持

\[
E_{d,t+1}=E_{d,t}+0.9c_{d,t}-\frac{b_{d,t}}{0.9}.
\]

边界为 \(1200\le E\le10800\) kWh，单槽充、放电上界均为 \(2500/3\) kWh，实际 SOC 跨日传递。题面未要求每日末 SOC 回到日初。

2. **官方时间映射与模板行列。** 延续已审计的官方行序，不额外解释时间标签物理起止含义；旧问题三已核验 `t=35,71,107` 分别进入 6:00、12:00、18:00 发布后的首个可调整后缀，结果模板正式期仍为 334 天 × 144 槽。

3. **附件 3 的因果解析和光伏左锚点原则。** 0:00、6:00、12:00、18:00 仅读取已发布的 24 个整点预测。整点到 10 分钟的主映射继续采用分段线性插值；发布时间左端不使用尚未证明确实已完成的附件 2 实测光伏，而使用上一轮已发布、目标为该时刻的预报。该映射仍是透明的建模假设，不是题面唯一指定。

4. **版本锁定、一次结算和审计字段。** 已执行槽位不得追溯修改；保留原计划、每轮版本、最终生效购电量、正负调整差额、费用明细和实际轨迹。按主结算解释，每槽只相对 0:00 原计划结算一次，避免多轮调整重复收费。

### 3.2 必须替换或重新评估的模块

1. **实时储能执行器必须替换。** 旧 `dispatch_q3_realtime.py` 在当前缺额下把参考日末 SOC 作为放电下限，属于阈值贪心规则；它不评估不同 SOC 的未来紧急购电机会成本。问题三 V2 应复用问题二 V2 的历史路径后向价值和连续 SOC 插值控制逻辑，但以问题三当前版本的剩余计划和当前可得情景为输入。

2. **日前模型必须升级。** 旧问题三是点预测 LP，并把 6000 kWh 作为日前软保留候选。问题二 V2 的终端库存价值 \(vE\) 可以作为候选的跨日机会成本近似，但 \(M=14\)、\(v=0.4\) 元/kWh、50 kWh 网格及任何日末参考水位不能直接宣称对问题三最优；它们须在问题三 1 月开发期按问题三费用口径重新评价。

3. **情景残差的定义必须改造。** 问题二 V2 的 PV 残差以“历史均值光伏预测”为基准；问题三在每个发布时点已有官方附件 3 预报。故问题三 V2 必须按预报版本定义残差，例如

\[
\epsilon^L_{i,t,k}=L_{i,t}-\widehat L_{i,t}^{(k)},\qquad
\epsilon^{PV}_{i,t,k}=PV_{i,t}-\widehat{PV}_{i,t}^{(k)},
\]

其中历史日 \(i\) 的预测版本 \(k\) 必须在当时真实可得。对当前发布版本，只能从早于决策日、具有同一信息结构的完整历史后缀取成对 \((\epsilon^L,\epsilon^{PV})\) 轨迹；不得把问题二 V2 的旧 PV 均值残差与附件 3 版本预报混合。

4. **旧全年结果需重新评价。** 旧问题三的全年结果使用点预测 LP、固定 6000 kWh 软保留和阈值贪心实时规则，故不能作为问题三 V2 的正式数值或参数依据。它仅保留为历史参考；所有 V2 对照都应以相同发布预报、同一初始协议、同一结算函数和同一因果审计重新运行。

## 4. 对六项重点问题的答复

| 问题 | 审计结论 |
|---|---|
| 旧问题三是否仍用贪心或其他实时规则 | 是。代码按 `reference_soc_end_kwh` 设置可放电下限，当前富余尽量充电、当前缺额在该下限之上尽量放电；这是阈值贪心，而非动态价值执行。 |
| 是否统一替换为问题二 V2 动态价值执行 | 是，但不能直接拷贝已冻结的日级价值表。每次 0:00/6:00/12:00/18:00 的生效购电版本和可见预报改变后，应对尚未执行的后缀重新基于当时历史情景构造 \(\bar H^{(k)}_{t+1}(E)\)。 |
| Q2 V2 的 \(M=14\) 是否可直接继承 | 可作为 V2 开发期候选和默认上限，不是继承即冻结的最优参数。问题三版本化 PV 预报会改变有效历史样本，必须逐日记录 \(M_{\rm eff}\)。 |
| 有官方 PV 预报后如何构造光伏残差 | 以每个历史日当时同发布时点、同样插值规则产生的 PV 预测为基准；在同一历史日内与负载残差成对保存。若同版本来源不足，应缩小 \(M_{\rm eff}\)，不得回填问题二历史均值 PV 预测。 |
| 日内调整后价值函数按哪个计划 | 按该时刻锁定的**当前最终生效计划后缀**计算。已执行槽位排除；原计划只用于结算基准，不能用于代表后续实际可用供电的价值函数。 |
| 旧全年结果和参数是否需重评 | 需要。旧参数只可作为候选或敏感性参考，不能直接迁入 V2 正式期。 |

## 5. 尚存题面歧义

1. 题面未唯一指定多次调整的比较基准，亦未明确下调部分是否先全额支付再退款。V2 暂沿用“最终生效量相对 0:00 原计划、每槽只结算一次”的主解释；必须继续在结果和论文中标为建模假设。
2. 附件 3 是整点功率预报，官方未规定其对应 10 分钟槽的转换。V2 暂继承线性插值和已发布预报左锚点；应在开发期保留一个不改变信息边界的映射敏感性小测试。
3. 附件未给官方负载预报。V2 必须使用纯历史、可回放的负载预测；选择哪一类（Q2 V2 同星期均值回退或旧 Q3 指数加权 + 已完成槽偏差校正）应在 1 月开发期比较后冻结。

## 6. 阶段 1 结论

问题三 V2 的设计审查可以进入**3 日最小闭环**，但仅限实现、审计和人工费用算例。通过发布版本可见性、已执行计划锁定、一次结算、SOC 跨日衔接、能量平衡及紧急购电不充电检查后，才可进入固定的 1 月开发评价；在此之前不得采用旧全年结果或写入 `result3.xlsx`。
